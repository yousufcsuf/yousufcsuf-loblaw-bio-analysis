# Loblaw Bio Immune Cell Analysis

## Overview

This project implements the four requested parts of the Loblaw Bio clinical-trial assessment.

It:

- loads `cell-count.csv` into a relational SQLite database
- calculates relative immune-cell frequencies for each sample
- compares miraclib responders and non-responders among melanoma PBMC samples
- performs statistical testing and visualization
- analyzes the requested baseline melanoma cohort
- calculates the requested average B-cell count
- provides an interactive Streamlit dashboard for Parts 2–4

Technologies used:

- Python
- pandas
- SQLite
- SciPy
- Plotly
- Streamlit
- pytest

---

# Part 1: Data Management

## Relational Database Schema

The source CSV contains three types of information:

1. subject-level information
2. sample-level information
3. immune-cell measurements

The database is normalized into three SQLite tables.

## `subjects`

Stores subject-level attributes:

```text
project
subject
condition
age
sex
treatment
response
```

Primary key:

```text
(project, subject)
```

The composite key allows subject identifiers to remain unique within each project.

---

## `samples`

Stores sample-level information:

```text
sample
project
subject
sample_type
time_from_treatment_start
```

Primary key:

```text
sample
```

Foreign key:

```text
(project, subject)
    REFERENCES subjects(project, subject)
```

A subject can have multiple samples at different timepoints.

---

## `cell_counts`

Stores one immune-cell measurement per row:

```text
sample
population
count
```

Primary key:

```text
(sample, population)
```

Foreign key:

```text
sample
    REFERENCES samples(sample)
```

The five cell-count columns from the CSV:

```text
b_cell
cd8_t_cell
cd4_t_cell
nk_cell
monocyte
```

are converted from wide format into long format before loading into SQLite.

Example:

```text
sample | b_cell | cd8_t_cell | cd4_t_cell | nk_cell | monocyte
S1     | 10     | 20         | 30         | 15      | 25
```

becomes:

```text
sample | population   | count
S1     | b_cell       | 10
S1     | cd8_t_cell   | 20
S1     | cd4_t_cell   | 30
S1     | nk_cell      | 15
S1     | monocyte     | 25
```

---

## Schema Rationale

The schema models the natural relationships:

```text
Subject
  |
  | one-to-many
  v
Sample
  |
  | one-to-many
  v
Cell Measurement
```

This reduces repeated data and makes analytical queries easier to maintain.

It also scales better if new immune-cell populations are added, because they can be inserted as additional rows in `cell_counts` without changing the schema.

---

## Scaling Considerations

SQLite is appropriate for this assessment because it is lightweight, reproducible, and easy to run in GitHub Codespaces.

For hundreds of projects, larger sample volumes, or concurrent production access, I would preserve the same logical schema but migrate to PostgreSQL.

Potential improvements include:

- indexes on `project`
- indexes on `subject`
- indexes on `sample`
- indexes on `condition`
- indexes on `treatment`
- indexes on `sample_type`
- indexes on `time_from_treatment_start`
- indexes on `population`
- batch loading
- cached or materialized analytical summaries
- PostgreSQL for concurrent workloads

# Part 2: Initial Analysis — Data Overview

The question is:

> What is the frequency of each cell type in each sample?

For each sample:

```text
total_count =
sum of all five cell population counts
```

For each population:

```text
percentage =
population count / total sample count × 100
```

The resulting table contains:

```text
sample
total_count
population
count
percentage
```

The output is written to:

```text
outputs/frequency_table.csv
```

The analysis also validates that each sample's percentages sum to approximately 100%.

---

# Part 3: Statistical Analysis

The responder comparison includes only:

```text
condition = melanoma
treatment = miraclib
sample_type = PBMC
response = yes or no
```

The analysis compares relative frequencies between:

```text
responders
vs
non-responders
```

for:

```text
b_cell
cd8_t_cell
cd4_t_cell
nk_cell
monocyte
```

---

## Statistical Method

A two-sided Mann–Whitney U test is used for each immune-cell population.

Because five comparisons are performed, Bonferroni correction is applied.

```text
alpha = 0.05
number of tests = 5

corrected threshold = 0.01
```

The statistical results are written to:

```text
outputs/statistical_results.csv
```

---

## Statistical Conclusion

After Bonferroni correction:

> No immune-cell population showed a statistically significant difference in relative frequency between miraclib responders and non-responders among melanoma PBMC samples.

This does not mean treatment response cannot be predicted. It only means that these five individual population frequencies did not show statistically significant differences under this analysis.

---

## Visualization

Responder and non-responder relative frequencies are shown using boxplots for each immune-cell population.

The visualization is available:

```text
outputs/responder_boxplots.html
```

and is also shown interactively in the Streamlit dashboard.

---

## Statistical Limitation

Subjects contribute repeated samples across timepoints.

Therefore, sample-level observations are not fully independent.

For a production longitudinal analysis, a mixed-effects or repeated-measures model would be preferable.
